# ReviewLoop 0.0.1

This release restarts ReviewLoop's version sequence and standardizes the project
license on **AGPL-3.0-or-later**. Historical releases and tags remain available.

## Included

- A standard stdio MCP server: `reviewloop mcp` exposes persistent review
  operations for generic MCP clients.
- One machine supervisor for explicitly watched projects, with shared provider
  budgets, persistent approval, task recovery and immutable PDF snapshots.
- Stanford Agentic Reviewer and CSPaper adapters, result archives, and CSPaper
  monthly usage reporting.
- Bounded provider diagnostics, API-key redaction in CSPaper failure messages,
  the Homebrew config-write fix, and `reviewloop --version`.

## Install and upgrade

Homebrew:

```sh
brew tap acture/ac
brew install reviewloop
# Existing installations:
brew update
brew upgrade reviewloop
```

The formula uses `version_scheme 1` so 0.0.1 upgrades historical 0.2.x installs.

Cargo:

```sh
cargo install reviewloop --version 0.0.1 --locked --force
```

Specify the version: unpinned Cargo installs still select the numerically higher
historical release. From 0.0.1 onward, `reviewloop self-update --method cargo --yes`
follows GitHub's designated latest release. `reviewloop --version` reports the
installed version.

Existing databases retain their history and migrate in place. The supervisor
runs watched projects only: use `reviewloop project watch`, then reinstall an
older single-project service with `reviewloop daemon install`. See the
[changelog](../../CHANGELOG.md) for command and schema changes.

## Validation and scope

The release is checked on Ubuntu and macOS, including real stdio MCP interaction
against mock review providers. The release workflow also verifies crate packaging
and a fresh Homebrew install/test before creating the GitHub release.

Authenticated end-to-end acceptance against Stanford and CSPaper remains pending.
Codex/Claude Code plugin packages and the shared agent skill are not included;
generic MCP configuration is documented in the README. Optional macOS GUI and
IMAP features are not part of the default-build acceptance.
